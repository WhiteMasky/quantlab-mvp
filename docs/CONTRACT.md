# QuantLab v0.1 engineering contract

## Ownership and safety
Coordinator owns quantlab/models.py, quantlab/engine.py, root manifests and lockfiles, frontend/package.json, frontend/tsconfig.json, frontend/vite.config.ts, scripts, README and integration reports. Each executor owns only its named quantlab module and tests/<module>. Product executor owns frontend/src, frontend/index.html and tests/e2e. Do not create subagents. Do not change shared models or dependency files; report requests. No live orders, external deployment, purchases, account changes, git commit/push. UI and API bind loopback only. No IBKR connection is attempted automatically.

## Common conventions
Read quantlab/models.py: this is authoritative. Imports use public package __init__.py exports. UTC-aware timestamps everywhere; session is America/New_York exchange trading date. XNYS calendar, DST and early closes are real calendar data. Prices, money and weights are Decimal, money rounded half-even to 0.0001 USD; quantities positive integer whole shares; float allowed only research metrics. API Decimal values are strings. jsonable serializes dataclasses. OHLC is raw executable price, adjusted_close is research-only. known_at/available_at gate observations. Costs are explicit hypothetical test assumptions, not a claim about current broker fees. Synthesized prices never count as investment evidence. Historical universe, delistings and point-in-time adjusted-data limitations must be exposed.

## Interfaces (all signatures exact; optional extensions allowed)
### data
- session_times(day: date) -> tuple[datetime, datetime] | None
- generate_synthetic(seed=7, sessions=504, symbols=('SPY','QQQ','IWM','TLT')) -> Dataset; fixed starting date, stable version hash.
- validate_dataset(dataset, now=None) -> list[dict] with severity/code/message/symbol as applicable.
- cache_dataset(dataset, path) -> Path; read_dataset(path) -> Dataset; Parquet with metadata/actions preserved.
- CSVDataSource.load(path) -> Dataset, documented strict raw and adjusted fields; no external download needed.
### research
- ExperimentRegistry(db_path): start(data_version, code_version, strategy, parameters, seed, synthetic) -> str; finish(run_id, result:dict, status='completed', error=None); list_experiments() -> list[dict]. UTC started/finished times, failures kept, SQLite.
- candidate_specs() -> list[dict] describes two predeclared hypotheses, small bounded parameter spaces, no optimization of holdout.
### strategy
- generate_signals(bars, as_of, strategy='trend', lookback=63, skip=5, top_n=2) -> list[Signal]. Filter availability before all calculations; trend and momentum deterministic; no broker imports. Reject invalid parameters. Insufficient history stays cash. Stable lexical ties. Signal eligibility means a candidate, not an order.
### portfolio
- allocate(signals, bars, as_of, max_weight=Decimal('0.35'), cash_buffer=Decimal('0.10'), vol_lookback=20, max_correlation=0.90, current_weights=None, turnover_limit=Decimal('0.30')) -> list[TargetWeight]. Long-only, volatility-aware, explicit correlation heuristic, turnover constraint.
- rebalance_orders(targets, account, prices:dict[str,Decimal], as_of, rebalance_key) -> list[OrderIntent]. Sells before buys, deterministic SHA-based intent/client IDs; removed symbols sold; no negative shares; reserve fees/buffer rather than borrowing.
### risk
- RiskLimits dataclass (module-owned) configurable limits for position/order notional, exposure/leverage, cash buffer, daily loss, drawdown, pending orders/rate, stale quotes/price deviation.
- RiskDecision dataclass: allowed:bool, reasons:list[str].
- RiskEngine(db_path, limits=None): check(intent, account, quote_price, quote_at, now, open_orders=0, reserved_cash=Decimal('0'), market_open=True) -> RiskDecision; set_halt(halted:bool, reason:str); status() -> dict; audit() -> list[dict]. Persist halt and loss/high-water/rate state. Risk checks never send orders/cancel/liquidate. Halt only stops NEW orders. No implicit liquidation. Fail closed on uncertainty. To test historical executions pass explicit historical now and current open quote (not previous close).
### backtest
- run_backtest(dataset, target_fn, config=None) -> BacktestResult. target_fn(known_bars:list[MarketBar], as_of:datetime, account:AccountSnapshot) -> list[TargetWeight]. Signals computed after available_at, fill no earlier than later session open; raw open + adverse half-spread/slippage. Consume only prior-known volume for participation budget (do not look at current full-day volume for an opening execution). Sells before buys; no short/margin; commissions; partial/unfilled DAY expired; optional GTC; cash/position ledger; idempotent fill application. Process splits and cash dividends once (never dividend plus adjusted execution prices). Explicit limitation for fractional cash-in-lieu/payment-date approximation if any. Public Ledger class for fill/idempotency tests. Backtest may import portfolio and risk using their contracts; each order MUST call independent RiskEngine.check. Risk refusal captured in Order reason.
### validation
- performance_metrics(curve, fills, initial_cash) -> dict containing total_return, annualized_return, max_drawdown, drawdown_duration, volatility, sharpe, sortino, turnover, fee_ratio, market_exposure, sample_size; finite values or None with explanation.
- validate_strategy(dataset, evaluator, parameter_grid, seed=7) -> dict; evaluator(subset:Dataset, params:dict, cost_multiplier:float) -> BacktestResult. chronological train/validation/untouched test, training warmup explicit (evaluation periods must not score warmup), small predeclared grid, choose with validation only then single final holdout evaluation, rolling OOS, costs 1/2/3, sensitivity, phase performance, bootstrap uncertainty and search count. Synthetic always passed=False, verdict='NOT_VALIDATED_SYNTHETIC'. No claim of statistical edge, no automatic tuning after holdout. Keep compute bounded (<= 12 primary evals preferred). Can expose split helpers for tests.
### broker
- SimulatedBroker(db_path): submit(intent)->Order; fill(order_id, quantity, price, commission, at, fill_id=None)->Fill|None (duplicates harmless); cancel(order_id, authorized=False)->Order; orders()->list[Order]; fills()->list[Fill]; disconnect(); reconnect(); reconcile(account=None)->dict; status()->dict. Persistent intent dedup, duplicate and out-of-order callback checks, unknown timeout halts/resend prevention. Initial offline simulator is reconciled. Restart with unresolved intent requires explicit reconcile. Live disabled.
- IBKRConfig and IBKRAdapter: optional official ibapi EClient/EWrapper adapter with explicit local paper account configuration; no guessed socket ports, no account-prefix-only environment verification, refuse live and unknown environments. Current official docs (checked by coordinator 2026-11-21) https://interactivebrokers.com/docs/tws-api/doc/notes-limitations/requirements.md require Python >=3.11 and current stable/latest matching TWS/API. Python here is 3.10; offline runs may use it but real adapter must reject it. Before coding broker inspect official docs at interactivebrokers.com/docs/tws-api/doc/{api-settings,quick-start/installation,order-management/order-status,order-management/execution-details,orders/place-order,orders/cancel-order,connectivity/establishing-an-api-connection}.md. ibkrcampus.com returned 403; interactivebrokers.com mirror works. Document fetched evidence in docs/IBKR.md (broker owns this doc and config.ibkr.example.json). Do not install random stale PyPI ibapi. Fail closed if account environment cannot be reliably verified (acceptable to keep submissions blocked pending external attestation/verification; clearly report limitation). Queries, heartbeat, pacing/errors, recovery snapshots completed callback barriers and locally durable IDs required. Broker adapter is called ONLY through coordinator execution gateway; strategy never imports it.
### coordinator engine (provided by coordinator; service/product may implement against this contract)
- Platform(runtime_dir: Path|string): snapshot()->dict; run_demo(strategy='trend', lookback=63, seed=7)->dict; set_halt(halted:bool, reason:str)->dict; cancel_all(authorized=False)->dict.
- snapshot dictionary keys: environment='SIMULATED', live_enabled=False, broker (status dict), data (source, synthetic, version, symbols, start, end, issues, limitations, updated_at), portfolio (cash,equity,positions list of symbol/quantity/average_cost/market_price, exposure), orders (list), fills (list), experiments (list), risk (dict), audit (list), latest_run (dict or None), alerts (list[str]). Empty initial state is valid and honest.
- run_demo returns run_id, strategy, parameters, synthetic=True, result (serialized BacktestResult with metrics, benchmarks, curve), validation (dict verdict and limits), execution (orders/fills counts), warnings. Offline demo only, no broker connection. Actual orchestration dataset -> strategy -> portfolio -> independent risk -> SIMULATED broker -> fills -> Ledger. Backtest history is separate from current execution ledger, clearly labelled. Failure experiments persisted. Idempotency same execution key, no repeated buying on identical rerun.
### service
- create_app(runtime_dir=None) -> FastAPI; app module singleton for uvicorn quantlab.service.app:app.
- GET /api/health, GET /api/state; POST /api/runs JSON {strategy:'trend'|'momentum',lookback:63,seed:7}; POST /api/risk/halt {halted:bool,reason:str}; POST /api/orders/cancel {authorized:true}. No liquidation endpoint. Do not expose broker submit/connect live endpoints. GET /api/experiments, /api/audit optional convenience. Local job locking serializes writes; safe SQLite and thread handling; validate inputs; reject non-local host/origin for mutation (CSRF protection). Mutations require application/json. Frontend Vite binds 127.0.0.1:15173 and proxies /api to 127.0.0.1:18765. Only the explicitly thread-safe emergency_halt capability uses a separate control lane; resume/cancel/research remain serialized. No credential/full account logging. Persist API audit in module-owned SQLite table. Engine import can be lazy until file delivered. No hidden fallback fake results on failure.
### product / tests
React TypeScript, native SVG charts (no chart library required), lucide-react available. Six navigation pages: overview, data, research, portfolio, orders/fills, risk/audit. Prominent text SIMULATED / SYNTHETIC; IBKR not connected; no live toggle. Offline run button calls /api/runs, editable strategy and lookback. Show pending/errors, disabled duplicate request, data disclosures and validation verdict. Halt stops new orders, separate explicit cancellation confirmation; NO flatten button. Accessible labels. Never fabricate placeholder return numbers; empty state until actual backend data. Frontend contract with service above. Product owns frontend/src, frontend/index.html and tests/e2e only (do not edit package.json/config). Use Vitest + Testing Library for UI tests; Python TestClient e2e for workflow. Coordinator will start servers and do browser testing. Include responsive polished console.

## Test execution
Use .venv/bin/python -m pytest tests/<owned-module> (dependencies installed centrally). Frontend uses coordinator .tools/node/bin/node and npm (PATH .tools/node/bin). Avoid polling other agents. Implement unit tests using shared models and local fixtures. Do not run full integration suite while others edit; coordinator runs at most three complete integration/fix rounds. Keep tests deterministic, external calls optional and never default. Report files, actual tests, and unverified limitations truthfully.
